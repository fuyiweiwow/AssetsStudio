# 功能：Actor 五步装配工作流

- 功能 ID：`F002`
- 状态：`in_progress`
- 负责人：Codex 与用户共同审查
- 建立时间：2026-08-09
- 最近更新：2026-08-09
- 关联里程碑：body、face、hair、tops、pants、shoes
- 关联 ADR：ADR-0002

## 需求证据

用户需要 Studio 呈现真实的资产生成/装配流程，而不是一组只改变文字详情的左侧 Tab。目标路径是“选择模型 → 选择骨骼 → 选择动画 → 选择拼装部件 → 预览最终组合”。当前只有一套 Actor、骨骼和 Walk，因此先实现诚实的单选工作流；多模型导入、自动绑定和动画重定向不得伪装成已经可用。

## 范围

- 建立五步可点击工作流，每一步切换到对应配置与说明。
- 模型、骨骼和动画读取当前 GLB manifest，并显示为唯一已选项。
- 拼装步骤允许检查并显示/隐藏发型、五官、上衣、短裤和鞋。
- 选择拼装部件时把镜头定位到相应区域。
- 结果步骤汇总模型、骨骼、动画和已装入组件。
- 支持播放、暂停、停止、时间轴、固定四视角和直接拖动自由旋转。

## 非目标

- 本轮不实现第二套模型、第二套骨骼或动画资产库。
- 不实现自动蒙皮、骨骼重定向、权重修复或跨体型服装适配。
- 不实现节点/蓝图编辑器和 Blender 作业队列。
- 不把尚未装入组合 GLB 的发型显示为可用组件。

## 用户操作路径

1. 双击 `start-studio.cmd` 启动本地 Studio。
2. 在左侧依次检查模型、骨骼和动画的唯一当前选项。
3. 进入“拼装部件”，选择部件定位镜头，并用显示开关组成 Actor。
4. 使用播放/暂停/停止、时间轴和拖动旋转检查组合。
5. 进入“结果预览”查看组合摘要；后续功能再把该组合保存为 Recipe。

## 输入与输出

| 类型 | 内容 | 格式/合同 |
| --- | --- | --- |
| 输入 | 正式资产状态 | `docs/ASSET_STATUS.json` 派生注册表 |
| 输入 | 模型、骨骼、动画、组件与眨眼状态 | `actor-composite-v1.glb` + manifest |
| 输出 | 当前页面装配状态 | React 内存状态；尚不持久化 |
| 输出 | 交互预览 | Three.js 单 Actor 实例 |

## 技术选型

| 问题 | 当前选择 | 原因 | 替代方案及未选原因 |
| --- | --- | --- | --- |
| 流程表达 | React 五步状态机式导航 | 当前步骤少、依赖线性明确，能诚实表示单选与未实现能力 | 节点编辑器适合未来复杂分支，但当前会增加无效复杂度 |
| 选项来源 | 注册表 + GLB manifest | 模型/骨骼/动画和组件均可追溯到导出报告 | 前端硬编码会与 Blender 输出漂移 |
| 组件检查 | 显示开关 + 分类镜头焦点 | 不修改模型即可立即检查装配关系 | 高亮材质会改变外观，可能掩盖真实问题 |
| 自由观察 | 任意视角均可直接拖动，拖动后进入自由模式 | 降低发现交互入口的成本，固定按钮仍可复位 | 只在“自由”按钮后允许拖动不够直观 |

## 数据合同与模块边界

- Blender 导出器负责声明 `model`、`rig`、`animations`、`components` 和 `face`。
- React 工作流只选择和预览已经登记的内容，不执行 Blender 绑定。
- `workspace/` 继续承载本地生成结果；未来 Recipe 持久化必须遵守 ADR-0002。
- 多模型支持前必须先定义统一骨骼合同与绑定/重定向作业接口。

## 风险与已知限制

- 当前三个选择步骤只有一个选项，重点是建立正确合同，而不是制造虚假的可选内容。
- 拼装状态尚未保存为 Recipe，刷新页面会恢复默认值。
- 发型已有来源合同，但尚未装入当前组合 GLB。
- 自动绑定是后续独立功能，需要模型骨骼映射、权重迁移、动作重定向和失败审查。

## 实现状态

第一检查点已完成五步页面、组件镜头定位、显隐控制、显式播放/暂停/停止、时间轴和直接拖动旋转。模型/骨骼/动画暂时各一项，但数据来自当前导出 manifest。等待用户人工审查后再决定进入 Recipe 保存还是多资产导入。
