# 功能：首套发型 Bundle 接入

- 功能 ID：`F004`
- 状态：`in_progress`
- 负责人：Codex 与用户共同审查
- 建立时间：2026-08-09
- 最近更新：2026-08-10
- 关联里程碑：hair、body
- 关联功能：F001、F003

## 需求证据

Actor 基准页已经能检查身体、骨骼、Walk、五官和服饰，但当前组合 GLB 的 `hair` 组件为空。用户决定下一步先接入发型。历史发型合同已经保留 Chloe/Colin 源、组件目录、正式随机池和固定种子，因此本轮不能重新测量 Demo 或任意拼装，必须复用现有 Actor 贴合参数。

## 范围

- 采用历史推荐女性种子 `seed_04_bangs04`：`Chloe_hair_back_01 + Chloe_hair_side_01 + Chloe_hair_bangs_04`。
- 复用 `chloe_randomization_seeds_v1.json` 的 Actor 贴合合同：`q_height_ratio=1.15`、`width_ratio=1.18`、源组件布局归一化。
- 生成一套可复现的 Actor 发型候选 Blend 和四视图审查图。
- 将候选作为单个 `hair` 组件接入 Studio 组合 GLB，并转换为 100% `CC_Base_Head` 蒙皮网格。
- 在资产仓库显示该候选的本地静态缩略图。
- 在网页检查正、右、背、左、Walk 和组件显隐。

## 非目标

- 本轮不批量接入全部男女发型。
- 本轮不把候选自动晋级为 `accepted`；用户人工审查前，发型里程碑仍是 `source_contract`，首套 bundle 为 `provisional`。
- 本轮不实现 Blender 后台作业队列或网页端几何随机生成。
- 不添加遮掩头皮问题的临时网页补丁；若四视图存在缺口，应回到可复现 Blender 候选修复。

## 用户操作路径

1. 启动 Studio，进入“资产工作台 → 发型”。
2. 在资产仓库查看首套发型静态图。
3. 在“单独展示 / Actor 搭配”间切换，检查四视角和 Walk。
4. 进入“Actor 基准”或“组合预览”，开关发型并检查整体装配。
5. 用户给出人工结论后，决定保留、修复或替换候选。

## 技术选型

| 问题 | 当前选择 | 原因 | 替代方案及未选原因 |
| --- | --- | --- | --- |
| 首套发型 | 历史推荐 `seed_04_bangs04` | Gallery 目录将其作为女性推荐预览，且组件/参数均已记录 | `seed_01` 只是基础；重新随机会失去历史证据 |
| 贴合 | 既有 `fit_blend_hair_candidate.py` 参数合同 | 避免再次测量 Actor、重复旧实验 | 手工移动无法复现；重新开发贴合器没有证据 |
| 网页绑定 | 单骨 `CC_Base_Head` 蒙皮 | 与已修复眼睛 glTF 合同一致，避免 Bone Parent 在 Three.js 中产生局部变换差异 | 网页每帧手工跟随会形成专用 workaround |
| 缩略图 | 从候选正面视图生成一张固定角度本地缓存 | 仓库卡片可快速识别组件，避免多视图缩略图造成信息拥挤且不膨胀 Git | 浏览器临时截图不可追溯；空占位无法审查 |

## 数据合同与模块边界

- 正式随机池仍只描述可参与组合的源组件，不因首套网页接入而自动晋级完整样式。
- 候选 manifest 必须记录源对象、贴合参数、Actor、输出和审查状态。
- Studio 导出 manifest 的 `components.hair` 必须非空，并记录 `hair.bundle_id`、组件列表、头骨和候选来源。
- GLB 验证器必须检查发型节点属于 `hair` 组件且引用 Actor skin。

## 验收条件

- [x] 自动验证：候选可重建，GLB 中发型非空、已蒙皮且包含 Walk。
- [x] 网页检查：发型开关有效，正侧背位置正确，随头部动画且不独立晃动。
- [ ] 人工审查：无明显头皮暴露、穿耳、后脑缺失或遮挡眼睛。
- [x] 文档同步：功能记录、开发时间线和发型工作流与实现一致。

## 风险与已知限制

- 历史 Gallery 图片缓存没有迁入仓库，`seed_04` 的视觉结论必须用当前 Actor 重新生成并由用户复核。
- Chloe 组件源使用展示网格位置，必须执行 `normalize_source_component_layout`。
- 当前首套发型只验证同一 Actor/Head Bone，不证明所有组件可直接批量接入。
- v2 已消除自动投影检测中的头皮暴露；由于尚未获得用户对新网页/GIF的最终视觉结论，人工验收仍未通过。

## 实现状态

首套候选 v2 已完成确定性重建、配方验证、四视图渲染、GLB 接入、缩略图缓存和投影覆盖检查。发型节点使用与眼睛相同的“评估后静止姿势网格 + 单骨蒙皮”导出合同，正、侧、背位置正确并随 `CC_Base_Head` 和 Walk 移动。512px 浅色 Actor 四方向 Walk 审查结果位于 `workspace/cache/hair/first_bundle_v2/walk_review/`。

首次网页导出曾直接把 Bone Parent 网格改成简单单骨权重，丢失父级变换，导致发型落在 Actor 脚边且不可见；现已改为评估静止姿势后再烘焙到 Actor 坐标。v1 中分亮缝经前向射线检测确认是中心发片比头皮更靠后，而非左右发片断开；v2 只把该局部区域平滑向前移动，暴露采样由 105 降为 0。源头皮补片和平滑补片仍保持拒绝状态。
