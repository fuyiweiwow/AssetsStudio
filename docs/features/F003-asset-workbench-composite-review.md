# 功能：资产工作台与组合预览分层

- 功能 ID：`F003`
- 状态：`in_progress`
- 负责人：Codex 与用户共同审查
- 建立时间：2026-08-09
- 最近更新：2026-08-09
- 关联功能：F001、F002
- 关联里程碑：body、hair、face、tops、pants、shoes

## 需求证据

用户指出当前页面把资产工作流、单项检查和最终组合预览混在同一界面；“配件控制台”缺少正式产品结构，发型也被遗漏。用户要求每类资产拥有单独工作流预览，并能在“单独展示 / Actor 搭配”之间切换；最终搭配应进入独立的组合预览界面。用户同时再次确认 Blender GIF 中眼睛正确、网页眼睛仍不正确，因此网页不能用 Blender 通过结论替代实际验收。

## 范围

- 顶层拆分为“资产工作台”“组合预览”和“Actor 基准”三个 Tab；基准页只负责网页端模型/骨骼/动画装配验收。
- 工作台按模型、骨骼、动画、发型、五官、上衣、裤子和鞋分为独立工作流。
- 外观资产工作流提供“单独展示 / Actor 搭配”预览模式。
- 发型读取现有男女组件目录、正式随机池和 Gallery 注册表，不再作为缺省配件占位。
- 建立正式的资产信息、预览、参数/随机化能力状态和已知问题区域。
- 工作台提供静态资产仓库；启动时从权威里程碑图片生成本地缓存，不为缺图资产伪造缩略图。
- 3D 工作区支持一键放大，放大时收起工作流和控制台，仍保留视角、动画和时间轴。
- 发型先实现确定性前端配方抽取；真正的 Blender 组合生成与 Actor GLB 替换留给作业桥接功能。
- 修复网页眼睛的 glTF 绑定合同，并以网页正侧背、动画与眨眼实际表现验收。

## 非目标

- 本轮不实现 Blender 后台作业服务、作业取消或候选清理器。
- 不承诺发型组件在尚未生成 Actor bundle 时立即出现在组合 GLB 中。
- 不实现节点/蓝图编辑器；先稳定普通表单和 Recipe 字段。
- 不在网页端隐藏短袖、短裤里程碑已有的模型缺陷。

## 分类边界

“配件”不再作为发型和服装的总分类。正式分类为：

1. 结构：模型、骨骼、动画；
2. 外观：发型、五官；
3. 服装：上衣、裤子、鞋；
4. 配件（预留）：帽子、眼镜、首饰、武器等不改变以上资产主合同的附加物。

发型具有 base、刘海、侧发、后发、兼容矩阵和随机池，是独立资产工作流。上衣、裤子和鞋也分别保留自己的参数合同、生成器和审查门槛。

## 用户操作路径

1. 在“资产工作台”依次选择结构或外观/服装工作流。
2. 选择某项资产后，在“单独展示 / Actor 搭配”之间切换并检查四视角和动作。
3. 在右侧查看来源、状态、已知问题及当前是否支持参数化/随机化。
4. 发型可以选择性别和随机种子，抽取满足必选槽位的配方；尚未接入 Blender 作业时明确显示“配方已生成、模型预览待生成”。
5. 点击“查看组合预览”进入独立 Tab，检查当前所有已装入组件；从该页可返回对应资产工作流。

## 技术选型

| 问题 | 当前选择 | 原因 | 替代方案及未选原因 |
| --- | --- | --- | --- |
| 页面分层 | React 顶层三 Tab | 明确区分制作决策、最终搭配和基础装配验收，同时保留同一应用状态 | 单页三栏会继续混淆任务；独立窗口会割裂状态 |
| 静态资产识别 | 注册表缩略图 URL + 本地生成缓存 | 复用已认可的里程碑审查图，启动时可重建且不膨胀 Git；缺图状态诚实可见 | 浏览器临时截图不可追溯；把所有缓存提交 Git 会持续增大仓库 |
| 资产工作流 | 分类步骤 Rail + 正式 Inspector | 当前资产类型固定，普通表单更适合先稳定合同 | 节点编辑器在 Recipe 未稳定前只会复制业务规则 |
| 单项预览 | 同一 GLB 的受控显隐 | 已装入组件可以即时切换且保持同一骨骼动画 | 为每项维护手工 GLB 会造成版本漂移 |
| 发型随机化 | 读取正式池并由 seed 确定性抽取 Recipe | 复用既有数据，不伪造几何生成能力，可直接成为作业桥输入 | 纯 `Math.random()` 无法追溯；任意笛卡尔积违反现有发型合同 |
| 网页眼睛 | 贴合网格转为 100% Head Bone 蒙皮后导出 | Blender Bone Parent 节点在当前 glTF 中没有 skin，产生巨大局部变换，不能作为 Three.js 动画真值 | 继续依赖 Bone Parent 或网页每帧手工贴头都缺少可靠导出合同 |

## 数据合同与模块边界

- `asset-registry.json` 增加发型目录摘要、正式随机池和 Gallery 元数据。
- 前端配方抽取只生成可追溯选择，不修改正式随机池，不宣称已生成模型。
- `ActorPreview` 接受 Actor 身体显隐和组件显隐合同；Armature 始终保留以驱动单项动画。
- Blender 导出器必须把网页眼睛导出为带 `skin` 的网格；验证器检查六个眨眼状态节点均引用同一权威 Skin 合同。
- 最终 Blender/GIF 仍是里程碑视觉真相，但网页预览必须独立通过网页人工检查。

- [x] 有权威静态图的五官、上衣、裤子和鞋显示缓存缩略图；身体和发型缺图时不伪造结果。

## 风险与已知限制

- 发型 Gallery 的历史渲染缓存没有迁入正式仓库；本轮先恢复目录和工作流合同，新的可视预览应由当前 Actor 重建，而不是引用失效路径。
- 当前组合 GLB 尚未包含发型，发型工作流会诚实显示“未装入”，不能用空白画面冒充生成失败。
- 单独展示仍使用组合 GLB 中的同一网格和骨架，仅隐藏 Actor 表面，不等同于独立 Blender 场景。
