# 功能：Studio 外壳、资产注册表与 Actor 预览

- 功能 ID：`F001`
- 状态：`proposed`
- 负责人：Codex 与用户共同审查
- 建立时间：2026-08-09
- 最近更新：2026-08-09
- 关联里程碑：body、hair、face、tops、pants、shoes
- 关联 ADR：ADR-0001、ADR-0002

## 需求证据

用户需要在资产调参或随机生成后留在同一页面查看结果，并且必须把结果放在当前 Actor 身上观察。用户同时要求生成结果可追溯、默认只留本地、方便清理，并最终为 BomboAdventure 提供版本化角色资产包。

F001 先建立可信的可视化与数据入口：让 Studio 能回答“当前有哪些正式资产”“它们是什么状态”“Actor 和动作能否在浏览器中正确显示”。生成作业和完整清理器在后续功能中实现，但 F001 不得设计出与 ADR-0002 冲突的数据结构。

## 范围

- 建立 TypeScript 前端工程和 Studio 基础页面布局。
- 从统一资产注册表读取六类当前里程碑、状态、来源和已知限制。
- 用可复现 Blender 脚本从权威 Actor 场景导出预览 GLB。
- 在 Three.js 中显示 Actor，并播放已验证的 Walk 动画。
- 支持正面、右侧、背面、左侧及自由旋转视图。
- 显示/隐藏当前可兼容的发型、五官、上衣、短裤和鞋预览组件。
- 展示加载、错误、空资产和格式不兼容状态，不静默回退到错误模型。
- 为后续 Recipe 和运行记录预留版本化 Schema 目录。

## 非目标

- F001 不直接实现参数化生成、随机化作业或 Blender 作业队列。
- 不实现节点/蓝图编辑器。
- 不实现云账号、数据库或多人协作。
- 不宣称 Three.js 预览等同于 Blender 最终 GIF。
- 不解决短袖与短裤里程碑本身已有的视觉缺陷。

## 用户操作路径

1. 用户启动本地 Studio。
2. 首页显示 Actor 预览和六类资产状态。
3. 用户选择当前里程碑组件，预览自动更新到 Actor。
4. 用户切换正侧背视角，播放、暂停或拖动 Walk 动画时间。
5. 用户打开资产详情，查看来源、状态、已知限制和对应人工审查材料。

## 输入与输出

| 类型 | 内容 | 格式/合同 |
| --- | --- | --- |
| 输入 | 当前资产状态 | 从 `docs/ASSET_STATUS.json` 派生的前端资产注册表 |
| 输入 | Actor、组件与 Walk 动画 | Blender 权威源，经固定导出脚本生成 GLB |
| 输出 | 浏览器预览 | 本地页面，不产生正式资产 |
| 输出 | 导出报告 | GLB 文件哈希、源提交、对象/动画清单和导出时间 |

## 技术选型

| 问题 | 当前选择 | 原因 | 替代方案及未选原因 |
| --- | --- | --- | --- |
| 语言与构建 | TypeScript + Vite | 为 Recipe/资产合同提供类型约束，开发服务器和构建简单 | 原生 JavaScript 缺少合同约束；Next.js 对本地工具过重 |
| UI | React | 适合资产列表、参数面板、作业状态和后续节点界面 | 原生 Web Components 需要更多自建状态组织 |
| 3D 集成 | Three.js + `@react-three/fiber` | 保留 Three.js 能力并让场景状态与 React UI 协同 | 直接 Three.js 可行，但组件生命周期和 UI 同步代码更多 |
| 预览格式 | GLB/glTF 2.0 | 支持网格、材质、骨骼和动画，适合浏览器加载 | 浏览器直接加载 `.blend` 不可行；FBX 作为来源而非网页合同 |
| 权威转换 | Blender 无界面 Python 脚本 | 复用当前模型、骨架与已有脚本 | 手工导出不可复现 |
| 初期数据 | 版本化 JSON/JSON Schema | 前端、Python 和未来 Blender 作业可共享且可验证 | 数据库尚无必要 |
| 运行范围 | Windows 单用户本地优先 | 当前 Blender、资产路径和开发环境都在 Windows | 立即跨平台会扩大未验证范围 |

这些技术选择属于 F001 当前实现基线；若原型验证失败，必须在“技术决策历史”记录证据后更换。

## 数据合同与模块边界

- `studio/`：前端源码，不直接读取任意磁盘路径。
- `schemas/`：资产注册、Recipe 和运行记录的版本化 Schema。
- `public/assets/` 或开发服务器受控路由：只暴露登记后的 GLB 和预览文件。
- `tools/blender/`：权威 Blender 导出脚本。
- `workspace/`：本地导出和候选，不进入 Git。
- 正式预览 GLB 是否同步，必须由资产清单的 `storage_policy` 决定。

## 验收条件

- [ ] 前端可在本机一条命令启动，并显示明确版本信息。
- [ ] 六类里程碑状态与 `docs/ASSET_STATUS.json` 一致。
- [ ] Actor GLB 由脚本从正式 `.blend` 重建，不依赖手工导出。
- [ ] Actor 在页面中比例、方向、材质和骨骼动画正常。
- [ ] Walk 可播放、暂停和跳转时间。
- [ ] 正、右、背、左四个固定视角可重复切换。
- [ ] 至少形成一套 Actor + 当前上衣 + 当前短裤 +当前鞋的组合预览。
- [ ] 页面明确显示短袖/短裤的 `provisional` 状态和已知缺陷。
- [ ] 自动测试覆盖资产状态映射和缺失文件错误状态。
- [ ] 用户通过页面截图或录屏/GIF完成人工审查。
- [ ] `python tools/validate_studio.py` 通过，开发文档与时间线同步。

## 风险与已知限制

- 当前各里程碑不一定共享可以直接合并导出的对象命名和材质合同。
- Blender 到 GLB 的骨骼、动作命名和材质可能需要标准化步骤。
- 发型与五官目前主要是源合同/技术基线，未必能在 F001 首轮全部独立开关。
- 短袖和短裤仍是 `provisional`，浏览器预览只能忠实显示，不能掩盖缺陷。
- 第三方鞋许可证不明确，预览与仓库必须保持私有。
