# ADR-0001：开发记录系统

- 状态：`accepted`
- 日期：2026-08-09
- 范围：整个仓库

## 背景

AssetsLab 的长期实验产生了大量重复候选、已失效工作流和依赖聊天上下文的结论。上下文压缩后容易重复测量、选择错误模型或把失败方案误认为正式基线。

## 决定

AssetsStudio 使用五个互补记录层：

1. `PRINCIPLES.md` 记录长期原则；
2. `docs/features/*.md` 记录主要功能的当前设计和变更原因；
3. `docs/decisions/*.md` 记录跨功能技术决策；
4. `docs/DEVELOPMENT_LOG.md` 与 `docs/REMOVALS.md` 记录重要时间线和清理事件；
5. Git 保存精确文件历史。

关键文件由 `tools/validate_studio.py` 强制检查。

## 原因

单一长文档会再次膨胀，单靠 Git 又无法快速解释业务原因。分层记录可以让当前结论短而明确，同时保留决策和删除历史。

## 影响

- 每个主要功能开始时会增加少量文档成本。
- 技术变更和删除不能只改代码。
- 新环境可以通过固定阅读顺序恢复上下文。

## 被放弃方案

- 只依赖聊天记录：不可稳定检索，也会因上下文压缩丢失。
- 只维护一个总日志：会快速变成长而难以更新的流水账。
- 只依赖 Git 提交：能看到差异，但通常不能完整解释产品与技术原因。
