# ADR-0005：参数化幻想服装生产管线

- 状态：`proposed`
- 日期：2026-08-14
- 范围：F008、服装 Recipe、GarmentCode、Blender、Studio、ComfyUI
- 替代：无
- 被替代：无

## 背景

项目最终输出是 2D/像素化游戏素材，用户不会通过手工建模快速建立可用的游戏服装资产。现有 GarmentCode 能够根据当前 Actor 的测量和碰撞合同生成基础衣片，但还没有复杂幻想服装的生产边界。

## 决定

采用“主体衣片参数化 + Blender 基础组件 + Studio 配方 + 可选 AI 设计旁路”的方案：

1. GarmentCode 负责主体软性服装的纸样、接缝和静态仿真。
2. Blender Python/Geometry Nodes 负责已有组件的轮廓参数、简单装饰、绑定、动作修正和最终渲染。
3. Studio Recipe 是前端、生成器和审查记录之间的唯一服装业务合同。
4. 第一阶段只做单一主体服装 archetype，不同时解决整套多层服装。
5. ComfyUI/Stable Diffusion 只用于概念、配色、纹样和低分辨率参考；不作为几何、骨骼、拓扑或最终帧的权威来源。
6. 所有外部模型、LoRA、节点和参考素材必须经过许可证登记；未确认的内容不进入正式资产。
7. 服装候选必须回到当前 Actor、骨骼、Walk 和四向人工审查链，不能因参数生成成功而自动晋级。

## 原因

- 2D 输出更依赖轮廓、配色和动作可读性，而不是完整服装工业模拟。
- 当前 Actor 专用 GarmentCode 输入和 Blender 转移链已经提供了可复用基础。
- 参数化 Blender 组件能减少对手工建模技能的依赖，并保留确定性和批量生产能力。
- ComfyUI 的节点图和本地 API 适合做可追溯的设计辅助，但图像生成不能保证四向拓扑和动画一致性。
- 不引入付费工具为必要依赖，可以降低成本、许可证和换机风险。

## 不选择的方案

### 购买 CLO/Marvelous Designer 作为核心后端

它们适合人工高级服装设计和布料模拟，但会引入付费软件、版本、授权和自动化环境依赖；可以作为未来人工参考工具，不作为正式管线必需品。

### 让 AI 直接生成最终服装模型或 Sprite

难以保证四方向、帧间一致性、固定拓扑、Actor 绑定和可复现参数，因此只保留为设计探索旁路。

### 通过 Blender 手工建模完成每个服装

不符合用户当前技能和批量生产目标；Blender 应优先作为脚本化参数执行器，而不是要求用户手工操作建模界面。

## 影响

- 需要新增服装 Recipe Schema、生成器入口、候选 manifest 和 Studio 表单/作业状态。
- 需要先建立一个经过验证的长袍或短袍基础 archetype，再扩展袖子、帽兜和装饰组件。
- 服装视觉验收需要加入 64px/128px 低分辨率轮廓检查。
- ComfyUI 集成必须保持可选；即使另一台机器离线，主服装生成链仍应可以运行。

## 复审条件

第一主体服装实验完成后，根据重建确定性、动作稳定性、2D 轮廓和人工修改成本复审本 ADR。若 GarmentCode 对目标轮廓限制过大，再评估增加 Blender 参数化表面组件，而不是直接引入付费软件。
